Proposal · built on the Temporal + Substrate + OpenShell pilot

Hand a coding task to an agent, get back a reviewed pull request

A developer describes a small change in Slack. An AI agent does the work in a locked-down environment, proves it with the project's own tests, and opens a pull request for a human to review. It never holds a real password, it can't reach the open internet, and every step is on record.

The example used on this page /agent example-org/storefront: Add an "Export CSV" button to the Orders page A typical ticket: well understood, a few files, has tests, and nobody has had time for it this sprint.

    Benefits

    What each group gets

    Developers

    • Hand off well-defined tickets from Slack and get a pull request back
    • Review it like any colleague's PR: diff, test output, and a link to exactly what the agent did
    • Several tasks can run in parallel without tying up a laptop

    Security

    • No real API keys or GitHub tokens ever enter the agent's environment
    • Internet blocked by default; only Claude, GitHub and approved package registries are reachable
    • Tests run where the agent can't touch them, so results can't be faked
    • Every blocked attempt is logged with program and destination

    Engineering leads

    • A person approves before work starts and before anything merges
    • Retries are capped, so a stuck task comes back to a human instead of burning budget
    • Spend is tracked per team, and idle agents cost nothing while frozen

    Platform team

    • Crash-safe by design: jobs resume where they stopped
    • One workflow, swappable runtimes: Substrate, OpenShell or both
    • A complete audit trail for every run, searchable by user, repo and team
    Compared with today

    Claude Code on a laptop vs. this flow

    Claude Code on a laptop stays the right tool for hands-on, interactive work. This flow is for work you delegate and review later.

    Claude Code on a laptopDelegated agent flow
    Where credentials liveOn the developer's machine, readable by the agent's processesOutside the sandbox; the agent only sees placeholders
    Internet accessWhatever the laptop can reachBlocked except named services; attempts logged
    Who checks the resultThe developer, by running tests locallyA separate, sealed test room, then a human reviewer
    What's recordedLocal session historyFull step-by-step history per run, per user
    Waiting for reviewA terminal stays openThe agent freezes; resumes when comments arrive

    How we get there

    Implementation plan

    Done

    Pilot: prove the plumbing

    Job manager, both sandbox runtimes, approval step, retries, crash recovery, internet blocking, tamper-proof testing, combined Substrate + OpenShell runs.

    Phase 1

    One user, real Claude

    Swap the scripted agent for Claude Code. The API key is held by OpenShell and swapped in at the network edge. Upload a local project, run its own tests, return a patch.

    Done when a small real feature lands as a correct patch on one of our repos.

    Phase 2

    Pilot group of 2–3 developers

    Company sign-in on the front door and the sandbox gateway. A GitHub App opens PRs as the requesting user with short-lived, single-repo tokens. One shared cluster.

    Done when PRs arrive attributed to the requester and no real credential is ever visible inside a sandbox.

    Phase 3

    Teams

    A workspace and spend limit per team, secrets in a vault, per-repo internet allowlists, and the review-comment loop that wakes a frozen agent.

    Done when cost per team is visible and blocked attempts flow into security logging.

    Phase 4

    Scale

    Move to a cloud cluster, pack idle agents onto Substrate, add dashboards for throughput and cost per merged PR.

    Done when we can quote cost per merged PR and how long PRs wait for review.

    Claude access uses the company's API account. Anthropic doesn't allow products to run on individual Claude.ai subscriptions, so users sign in with company SSO and usage is billed to their team.
